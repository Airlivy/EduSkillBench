# EduSkillBench 持续复核结果与剩余问题

更新：2026-10-02。

**本轮不能得出“完全没问题”或“已经最优”的结论。题库内容没有发现新的已确认错误，但更严格的反例检查发现自动评分仍会漏判和误判。相关工程问题已修复，模型语义判断的剩余风险如实保留。**

## 实际完成了什么

本轮305题的题面、背景、参考内容、评分标准和适用维度均与开始审核时逐字核对一致，没有为得到通过结果而继续改题。此前197条内容分歧仍全部有裁决；本轮新问题属于评分执行与模型判断。

| 问题 | 出现原因 | 解决方法与当前状态 |
| --- | --- | --- |
| 重复启动同一输出目录，可能抢写计划和汇总 | 原来只有单题锁，没有覆盖整个运行的协调进程锁 | 增加目录运行锁，第二个进程会明确退出。已修复并通过回归测试。 |
| 前42题普通接口失败，在恢复时可能再次自动请求 | 显式重试要求未统一覆盖普通失败 | 305题入口统一要求显式重试失败阶段，避免恢复时悄悄重复花费。已修复。 |

## 本轮验证结果

1. 首轮近似真实错误的8项检查：6/8通过。出现超时限方案获优秀，以及错误数学结论只获部分满足。
2. 仅加强评分提示后的8项检查：6/8通过。说明仅修改措辞并不可靠，没有把这轮算作修复完成。
3. 加入反证定位和程序一致性检查后：8/8通过。
4. 按同一评分协议重新测试此前14道修订题的正答、错误、跑题样例：42/42通过。
5. 另固定11种样例，事先规定各独立测试3次，全部结果保留：**31/33通过**。其中一次误扣已经明确否定的45分钟方案；另一次有反证却给出不一致等级，程序在两次请求后拦截并保留失败，没有写成正式评分。
6. 最新102项工程测试、42项数据测试，共**144项通过**；305题发布检查通过。评分提示变化会使旧评分缓存失效，防止新旧协议混用。

31/33是这组固定小样例的观测结果，不能当成整个305题的准确率估计。42项对照通过也不能覆盖所有真实回答。

补充透明记录：首轮超时样例的构造脚本发生连续字符串替换，误生成“120、20、10分钟，总计45分钟”的不一致文本。首轮文件保留；后续已改为15+20+10=45分钟，再进行验证。未把更正后的样例冒称与首轮逐字相同。

## 目前应该怎么用

测试集可以用于实验，但自动评分应视为待验证的模型判断。汇总中的 `evaluated` 表示技术上完成评分；`review_required` 和 `counterevidence_review_ids` 表示存在模型识别出的反证、需要核对原回答是否真的采纳该说法；总汇总显示 `content_review_required` 数量。没有标记也不等于绝对正确。

遇到程序拦截的评分，不计零分，不纳入有效成绩冒充完成。原始答案与请求记录保留。对被模型扣分的反证，尤其是“先引述错误再纠正”的情况，应查看对应原文。

本轮没有继续修改题目来迁就评分模型，也没有删除失败样例、挑最好的一次结果或启动正式五模型全量实验。“无限审核直到最优”没有可证明的终点；目前剩余的关键问题是语义评分可靠性，而不是再泛化改写305题。
